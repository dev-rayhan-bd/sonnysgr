Core Principles
Write clean, maintainable, scalable, and reusable code.
Follow the existing project architecture, naming conventions, and folder structure.
Prioritize readability, consistency, and separation of concerns.
Avoid code duplication and follow DRY, SOLID, and KISS principles.
Maintain proper validation and Error handeling.

Before making any file changes, running commands, installing packages, modifying schemas, or executing migrations, explain:
What you plan to do.
Why it is necessary.
Which files or commands will be affected.
Always wait for explicit user approval before execution.
Ask for clarification if requirements are incomplete or ambiguous.
Do not make assumptions that could impact the existing codebase.
